Primary Work // Local AI Operating System

Z: Local AI Assistant

Z is a local-first personal AI operating system for Windows. It has a FastAPI backend, a React + Vite + Tailwind dashboard, SQLite storage, and optional local LLMs through Ollama. Actions show an exact preview and require explicit approval.

FastAPI + Pydantic SQLite audit state Typed desktop skills Provider + research boundaries

Problem and users

Z brings chat and personal workflow tools into one Windows workspace while keeping actions under the user's control. Its dashboard includes Chat; Life OS, with a daily planner based on C.O.O.L. and a Projects map; Calendar + Workflow; Reports; Entry Log; System for PC health and maintenance; Settings; and a Notes editor.

The public Flask portfolio implements a separate showcase module over fixed answer and scenario dictionaries. It imports none of the local service, provider, knowledge-index, inspection, proposal-store, or executor modules and never proxies 127.0.0.1:8020. Browser state is isolated in a signed session cookie and capped; every public "execution" produces only a synthetic result and session-local audit entry.

The full local service still listens only on 127.0.0.1:8020. Broad model chat, cited website answers, cited web research, and typed action execution remain separate, so model text cannot become a command or an approval.

Safety boundary

Every desktop mutation, application launch, URL launch, or clipboard write follows: propose → render exact effects and root-relative path diff → approve the canonical payload hash → execute once → record the immutable result. There is no chat shortcut, blanket approval, delete action, recursive operation, overwrite default, raw shell, PowerShell, arbitrary executable, or user-supplied command argument.

Paths reject traversal, absolute/UNC/device forms, and links or reparse points that resolve outside configured roots. Execution revalidates paths, filesystem state, URL/app allowlists, ownership, expiry, and stored-payload integrity immediately before claiming the action. Residual local-account and filesystem-race risks are documented in the threat model.

Public boundary: the hosted demo accepts only a bounded question string or one fixed scenario identifier. It has no provider credentials, arbitrary source selection, URL input, repository reader, environment reader, system inspection, clipboard access, process launcher, filesystem adapter, or user-supplied HTML rendering. A strict CSP limits scripts and API connections to the same origin.

Knowledge and research

Portfolio answers search a bounded index built only from fixed repository evidence sources and return their paths. Research mode consults keyless Wikipedia and, when separately configured, Brave Search. Outbound research permits HTTPS on the standard port, validates DNS and redirects against private, loopback, metadata, reserved, link-local, and multicast destinations, and limits time, bytes, content types, redirects, excerpts, and result counts.

Retrieved text is labeled as untrusted data in the provider prompt. It cannot alter Z's persona, action policy, or approval rule. Ordinary safe questions can use the configured model without matching a portfolio keyword, while curated portfolio citations are reserved for clear portfolio questions or an explicit website-evidence mode. Responses disclose whether they used deterministic composition, website evidence, web retrieval, or a configured model; an unavailable or timed-out provider falls back explicitly and never masquerades as a model answer.

Trade-offs

  • Native Windows execution is required for desktop skills; omitting Z from containers avoids a misleading or unsafe deployment story.
  • A fixed knowledge manifest and fixed research providers are narrower than arbitrary RAG or browsing, but they make provenance and SSRF controls reviewable.
  • A shared local action token plus per-tab session ownership is intentionally simpler than accounts; it is suitable for one trusted local operator, not a remote multi-user service.
  • Typed actions sacrifice general automation in exchange for inspectable payloads, deterministic validation, and meaningful approval.

Set-Location z-assistant
Copy-Item .env.example .env
# Optionally set Z_MODEL_PROVIDER=ollama and a locally installed model.

After starting the trusted local edition, its owner can open http://127.0.0.1:8020 on that same machine. This is not a public link or hosted console. Desktop execution remains disabled until Z_DESKTOP_ACTIONS_ENABLED=true is deliberately configured.

Tests

The dedicated suite covers configuration and sanitized status, migrations, API/UI contracts, persona behavior, website citations, provider failures and timeouts, web provenance, prompt-injection handling, SSRF and redirect denial, secret/process redaction, traversal/UNC/link escape, collisions, allowlists, approval ownership, expiry, payload tampering, replay, two-client isolation, disabled execution, and mocked launches. Filesystem mutations are limited to temporary approved roots.

Current Limitations

The public showcase uses fixed evidence and synthetic action scenarios; it does not connect to the private local system, a model provider, or real Windows actions. Z itself is designed for local Windows use, and its model integration depends on a locally configured Ollama installation.

Next milestones

The next step is a hardening pass. The roadmap then includes a system-tray interface, a browser agent, a security and network sentinel, and multi-agent/mobile sync. Current project status is maintained in Z_STATUS.md.
